  - 리랭커 구성: **첫 실행 61.2s → 캐시 후 3.6s**
  - FAISS 로드: 0.0~0.5s, **문서수 882**
  - → 캐싱(T1-1)이 없으면 Streamlit 재실행마다 13~62s 지연이 발생함을 실측 확인.

### 5.1 TP-A 리소스 로드 — ✅ PASS
`langchain_community.*` 마이그레이션(T1-3) 상태로 임베딩+FAISS+리랭커가 **deprecation/에러 없이** 로드됨.

### 5.2 TP-B 검색 모드 비교(dense vs hybrid vs hybrid+reranker) — ✅ PASS (중요 발견)
질의별 상위 3개 문서(제목):

| 질의 | dense-only | hybrid | hybrid+reranker |
|------|-----------|--------|-----------------|
| 말티즈가 자꾸 짖어요 | 말티즈(YT)×3 | 말티즈(YT)×3 (순서변동) | 말티즈(YT)×2 + **aggression in dogs(영문)** |
| 강아지가 분리불안이 있어요 | **separation anxiety in dogs×3**(kinship) | separation anxiety×2 + "6 lies..."(다양성↑) | ⚠️ **헝가리안 풀리/알래스칸 말라뮤트/이탈리안 그레이하운드(YT 견종)** |
| 강아지가 벽지를 긁어요 | scratch carpet + pawing×2(중복) | scratch carpet + pawing×2 | ✅ **scratch carpet + scratch bed×2**(주제 정확·다양성↑) |

**핵심 발견(리랭커의 양면성):**
- ✅ "벽지 긁기" 질의: 리랭커가 off-topic "pawing" 중복을 제거하고 carpet/bed 긁기 문서로 **개선**.
- ⚠️ "분리불안" 질의: 리랭커가 **정답(영문 kinship separation-anxiety)을 밀어내고 한글 YT 견종 문서를 1~3위로 올림 → 명백한 품질 저하**.
  - 원인: cross-encoder가 *한글질의↔한글문서* 점수를 *한글질의↔영문문서*보다 높게 매김(교차언어 약점). 주제 적합도(영문 분리불안 문서)보다 표면 언어 일치를 선호.
- ➡️ **결론: 리랭커를 기본 ON으로 두면 한글질의→영문문서 케이스에서 회귀 위험.** T1-4 번역 단계를 리랭커 앞에 두거나, 한글질의는 리랭커 비활성/언어 일관 검색이 필요.

### 5.3 TP-C dense-only 폴백 — ✅ PASS
`USE_HYBRID=0 USE_RERANKER=0` 경로(_build_retriever)가 에러 없이 dense 검색만 수행.

### 5.4 TP-D 출처 메타데이터 — ✅ PASS
모든 문서가 `keys=['source','title']` 보유 → T2-4 제목 링크 렌더에 필요한 `title`/`source` 확보 확인.
부수 발견: **DB에 동일 source 문서가 2~3회 중복** 존재(dense가 중복 반환) → 출처 dedup(T2-4) 및 인덱스 정리 필요성 실증.

## 6. 결론 및 권고

1. **모델/검색 계층(T1-1·T1-3·T2-1·T2-4)은 실모델로 검증 완료.** 마이그레이션 무결, 캐싱 효과(13~62s 절감) 실측, 세 검색 모드 동작 확인.
2. **리랭커 효과는 ragas 정량 평가로 재판정됨(§8).** 단일 쿼리(분리불안)에선 회귀로 보였으나, 11건 평균 **context_precision은 리랭커가 +0.091 우세(0.894→0.985)** — 검색 품질은 평균적으로 향상. 단 **faithfulness는 -0.047 소폭 하락**. 결론: 리랭커 **ON 유지가 검색 정밀도 기준 정당**하되, 특정 한글↔영문 케이스 회귀와 faithfulness 하락은 모니터링 필요. (이전 "USE_RERANKER=0 단기 권장"은 정량 데이터로 **완화/수정**.)
   - 중기: **T1-4 번역 → 검색 → 리랭크** 순서로 언어 정렬 후 리랭킹하거나 한/영 인덱스 분리로 회귀 케이스 보강.
3. **데이터 품질**: FAISS에 중복 문서 다수 → 인덱스 재구축 시 dedup 권장(검색 슬롯 낭비 방지).
4. **LLM 엔드투엔드(T1-2·T1-4·T2-3) 전부 실호출로 PASS.** 특히 T1-2 대화 메모리는 "그럼 어떻게 훈련해?" 후속 질문이 직전 말티즈·짖음 맥락을 정확히 계승함을 확인(가장 중요한 신규 기능). T2-3 범위 가드/면책, T1-4 교차언어 단일 답변도 정상.

### 7.3 전체 답변 예시(발췌)
**[10] 대화메모리** — 1턴 "비글은 어떤 견종이야?" 후

## 8. T2-2 ragas 정량 평가 (리랭커 ON vs OFF)
> 환경: `ragas 0.1.22`(설치 시 langchain 0.1.20/core 0.1.53 **무손상**, langchain-openai 0.1.7 동반). 평가 LLM/임베딩은 OpenAI 기본값.
> 데이터: `data/eval/testcases.json`(11건). 샘플 생성은 리랭커 ON/OFF 각각(`USE_RERANKER`), 평가는 동일 케이스. **N=11 소표본 → 방향성 참고용.**
> 실행: `eval_ragas.py --generate`(샘플) → `--evaluate`(채점). 결과 CSV: `data/eval/ragas_result_*.csv`(gitignore).

### 8.1 집계 점수
| 지표 | NORERANK (dense+hybrid) | RERANK (+bge-reranker) | Δ |
|------|:---:|:---:|:---:|
| faithfulness (답변의 문서 근거성) | 0.503 | 0.456 | 🔻 −0.047 |
| answer_relevancy (질문 적합성) | 0.369 | 0.364 | ≈ −0.006 |
| context_precision (검색 정밀도) | 0.894 | **0.985** | 🔼 **+0.091** |

### 8.2 해석 (per-case 기반)
- ✅ **리랭커가 검색 정밀도(context_precision)를 평균적으로 향상**(0.89→0.99). §5.2의 단일 쿼리(분리불안) 회귀 관찰과 달리, **11건 평균으로는 리랭커가 더 적합한 문서를 상위에 둠** → 정량 데이터가 우선.
- 🔻 **faithfulness 소폭 하락**(0.50→0.46): 리랭커 적용 시 일부 케이스에서 답변이 검색 문서에서 더 벗어남(예: TC01 1.0→0.09). 답변이 일반 지식에 의존하는 경향과 결합된 결과.
- ⚠️ **answer_relevancy는 두 설정 모두 낮음(~0.37)이나 신뢰도 주의**: 한국어 답변에서 ragas가 0점을 다수 부여(TC02·TC03 등 양질 답변도 0). 한국어/구조화 답변에 대한 ragas 임베딩 한계 → **절대값 과해석 금지**.
- ⚠️ **OOS 케이스가 평균을 끌어내림**: TC04(페럿)·TC10(고양이)은 의도된 범위외 거절이라 검색문서가 없고(placeholder) 질문에 "답"하지 않으므로 f/ar=0. **가드레일이 올바로 동작한 결과가 역설적으로 ragas 점수를 낮춤** → in-scope만 보면 실제 품질은 더 높음.

### 8.3 결론
- **리랭커 기본 ON 유지가 정량적으로 정당**(검색 정밀도 우세). 단 faithfulness 하락 + §5.2 한글↔영문 회귀는 잔존 → 중기 과제(언어 정렬/인덱스 분리)로 해소 권장.
- **faithfulness/answer_relevancy 저조의 핵심 원인은 코퍼스**: 건강/증상 문서 빈약(§7.2)과 한글 질의↔영문 문서 불일치. 데이터 보강이 모델/리랭커 튜닝보다 효과가 클 것으로 판단.
- 본 수치는 **N=11 소표본 + 한국어 ragas 한계**가 있으므로 절대 기준이 아닌 **회귀 감지·상대 비교용 베이스라인**으로 사용.
